Under the Hood

Security, layer by layer

Every control below is actually implemented and independently tested — not aspirational bullet points.

🔐

AES-256 Encryption

Diagnoses, treatment, prescriptions, test results & insurance data encrypted at the field level before they ever reach the database.

🧂

Bcrypt Password Hashing

Passwords are never stored or compared in plaintext — salted, adaptive-cost hashing throughout.

📟

Multi-Factor Authentication

Doctor & admin accounts require a one-time email code on top of a password before a session is ever fully trusted.

🔒

Account Lockout

Repeated failed logins automatically lock the account and alert an administrator — brute force gets nowhere.

🧭

Role-Based Access Control

Every endpoint checks role server-side. A patient token can never reach an admin route, full stop.

🤝

Consent-Based Record Access

A doctor sees a patient's chart only if that patient has actively granted — and not revoked — consent.

🛡️

CSRF Protection

Every state-changing request carries a session-bound token a third-party site could never obtain.

🧱

SQL Injection Prevention

100% parameterized queries — user input is never concatenated into SQL, anywhere in the codebase.

🧼

XSS Protection

All rendered output is HTML-escaped; a strict Content-Security-Policy blocks unauthorized scripts outright.

🪟

Clickjacking Defense

The app can never be embedded in a hidden iframe on another site — enforced via CSP and X-Frame-Options.

⏱️

Rate Limiting

Auth endpoints and the API as a whole throttle abusive request volume automatically.

📜

Full Audit Trail

Every login, view, and change is logged with identity, timestamp, and outcome — searchable by admins.

✍️

Digital Signatures

Every prescription is HMAC-signed at save time, so tampering after the fact is detectable.

🕰️

Record Versioning

Every edit to a medical record snapshots the prior version — nothing is silently overwritten.

🚪

Auto-Logout

Idle sessions expire automatically, with a warning before they do.

✅

Input Validation

Every request body, param, and query string is type- and format-checked at the boundary before it's trusted.
